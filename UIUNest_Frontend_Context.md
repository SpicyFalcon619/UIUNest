# UIUNest — Frontend Prototype Context
> Read this entirely before responding to any prompts or modifying any code.

## 1. Project Overview
**UIUNest** is a web-based housing, flatmate matching, and community marketplace portal exclusively for United International University (UIU) students. It solves problems with hidden housing costs, flatmate compatibility, and campus-based second-hand goods trading.

This is a **DBMS Lab Project** that will eventually be powered by raw PHP and MySQL. 

## 2. Current State of the Codebase
This codebase is a **Static Frontend Prototype**. It was initially generated by an AI tool that may have included unwanted build tools (like TypeScript, Vite, or package.json). 

**CRITICAL INSTRUCTION:** Ignore any TypeScript (`.ts`/`.tsx`), React, Node.js, or Vite configuration files in this directory. We are NOT using them. We are strictly working with the raw HTML, CSS, and Vanilla JavaScript files. 

## 3. Strict Tech Stack (Do NOT Deviate)
- **HTML5:** Standard, semantic `.html` files (which will later be renamed to `.php`).
- **CSS3:** A single `style.css` file.
- **Tailwind CSS:** Loaded exclusively via CDN (`<script src="https://cdn.tailwindcss.com"></script>`). Do NOT use npm to install Tailwind.
- **JavaScript:** Pure, vanilla JavaScript (`app.js`). NO frameworks (No React, Vue, jQuery, etc.).
- **Map & Charts:** Leaflet.js and Chart.js, both loaded via CDN.
- **Data:** All mock data is currently hardcoded in a `data.js` file attached to the `window.mockData` object. 

## 4. Architectural Rules for AI Edits
When I ask you to modify or add features to this frontend, you must obey the following rules:

1. **PHP Readiness:** Write HTML and JS in a way that makes it easy to convert to PHP later. Keep data rendering logic simple.
2. **The `data.js` Pattern:** If you need to add new mock data to display something, add it to the `data.js` file as a plain JS object/array, and then write vanilla JS in `app.js` to render it into the DOM. Do NOT hardcode text directly into the HTML if it is meant to be dynamic database content.
3. **Vanilla DOM Manipulation:** Use standard `document.getElementById`, `document.createElement`, `innerHTML`, and Event Listeners. 
4. **No Build Steps:** Never suggest running `npm install`, `npm run dev`, or compiling TypeScript.
